## 学習メモ

### Context APIの3つの主要要素

#### 1. createContext()
Contextオブジェクトを作成する関数。

```jsx
import { createContext } from 'react'

const ThemeContext = createContext()
```

初期値を渡すこともできる（省略可能）:
```jsx
const ThemeContext = createContext({ theme: 'light' })
```

#### 2. Provider
Contextの値を子コンポーネントに提供するコンポーネント。

```jsx
<ThemeContext.Provider value={/* 共有したい値 */}>
  {children}
</ThemeContext.Provider>
```

**重要なポイント:**
- `value`プロパティに渡したオブジェクトが、すべての子コンポーネントで利用可能になる
- Providerの子孫コンポーネントであれば、何階層深くてもアクセス可能

#### 3. useContext()
Contextの値を取得するフック。

```jsx
import { useContext } from 'react'

const value = useContext(ThemeContext)
```

### ThemeContextの実装詳細

#### 完全なコード構造

```jsx
import { createContext, useContext, useState, useEffect } from 'react'

// 1. Contextを作成
const ThemeContext = createContext()

// 2. カスタムフック（使いやすくするためのラッパー）
export function useTheme() {
  const context = useContext(ThemeContext)
  if (!context) {
    throw new Error('useTheme must be used within a ThemeProvider')
  }
  return context
}

// 3. Providerコンポーネント
export function ThemeProvider({ children }) {
  // LocalStorageから初期値を取得
  const [theme, setTheme] = useState(() => {
    const savedTheme = localStorage.getItem('theme')
    return savedTheme || 'light'
  })

  // テーマ変更時にLocalStorageに保存
  useEffect(() => {
    localStorage.setItem('theme', theme)
    document.body.className = theme
  }, [theme])

  // テーマ切り替え関数
  const toggleTheme = () => {
    setTheme(prevTheme => prevTheme === 'light' ? 'dark' : 'light')
  }

  const isDark = theme === 'dark'

  // 共有する値をオブジェクトにまとめる
  const value = {
    theme,
    isDark,
    toggleTheme,
  }

  return (
    <ThemeContext.Provider value={value}>
      {children}
    </ThemeContext.Provider>
  )
}
```

### 各部分の解説

#### useStateの初期化関数パターン

```jsx
const [theme, setTheme] = useState(() => {
  const savedTheme = localStorage.getItem('theme')
  return savedTheme || 'light'
})
```

**なぜ関数を渡すのか？**
- `useState('light')`だと、毎回レンダリング時に`'light'`が評価される
- `useState(() => ...)`だと、**初回レンダリング時のみ**関数が実行される
- LocalStorageへのアクセスは遅い操作なので、初回のみ実行することでパフォーマンス向上

#### useEffectでの副作用処理

```jsx
useEffect(() => {
  localStorage.setItem('theme', theme)
  document.body.className = theme
}, [theme])
```

**実行タイミング:**
- `theme`が変更されたときに実行
- LocalStorageに保存 + bodyタグにクラスを適用

**なぜbody.classNameを使うのか？**
- CSSで`body.dark .page { ... }`のように、bodyのクラスに応じてスタイルを切り替えられる
- 1箇所でクラスを変えるだけで、すべての子要素のスタイルが変わる

#### カスタムフックのエラーハンドリング

```jsx
export function useTheme() {
  const context = useContext(ThemeContext)
  if (!context) {
    throw new Error('useTheme must be used within a ThemeProvider')
  }
  return context
}
```

**なぜエラーを投げるのか？**
- ThemeProviderの外で`useTheme()`を使うと、contextは`undefined`になる
- 早期にエラーを検出し、開発者に正しい使い方を促す
- プロダクションでバグが発生するのを防ぐ

### App.jsxでのProvider配置

```jsx
function App() {
  return (
    <ThemeProvider>
      <BrowserRouter>
        <div className="app">
          <Navbar />
          <main className="main-content">
            <Routes>...</Routes>
          </main>
        </div>
      </BrowserRouter>
    </ThemeProvider>
  )
}
```

**重要なポイント:**
- `ThemeProvider`が最も外側（BrowserRouterより外）
- すべてのコンポーネントがテーマにアクセスできる
- Providerの順序は重要（外側のProviderから先に評価される）

### Navbarでのuseテーマの使用

```jsx
import { useTheme } from '../contexts/ThemeContext'

function Navbar() {
  const { isDark, toggleTheme } = useTheme()

  return (
    <nav className="navbar">
      <button onClick={toggleTheme} className="theme-toggle">
        {isDark ? '☀️' : '🌙'}
      </button>
    </nav>
  )
}
```

**Props不要:**
- Navbarは`theme`や`toggleTheme`をpropsで受け取らない
- `useTheme()`を呼ぶだけで、直接アクセスできる
- 親コンポーネント（App）を変更する必要がない

### ダークモードのCSS実装

#### bodyクラスによる切り替え

```css
/* ライトモード（デフォルト） */
.page {
  background: white;
  color: #333;
}

/* ダークモード */
body.dark .page {
  background: #2d2d2d;
  color: #e0e0e0;
}
```

**仕組み:**
1. JavaScriptで`document.body.className = 'dark'`を実行
2. `<body class="dark">`になる
3. CSSで`body.dark`以下の要素にスタイルが適用される

#### カラーパレットの設計

**ダークモード用の色:**
- 背景: `#1a1a1a`（ほぼ黒）
- カード背景: `#2d2d2d`（濃いグレー）
- テキスト: `#e0e0e0`（明るいグレー）
- リンク: `#8b9eff`（淡い青紫）

**ポイント:**
- 完全な黒（#000000）は避ける → 目に優しい
- コントラストを十分に確保 → 読みやすさ
- アクセントカラーは明るめに → クリックできることが明確

### Props Drillingとの比較

#### Props Drillingの場合（悪い例）

```jsx
// App.jsx
function App() {
  const [theme, setTheme] = useState('light')

  return (
    <Navbar theme={theme} setTheme={setTheme} />
  )
}

// Navbar.jsx
function Navbar({ theme, setTheme }) {
  return (
    <Menu theme={theme} setTheme={setTheme} />
  )
}

// Menu.jsx
function Menu({ theme, setTheme }) {
  return (
    <Button theme={theme} setTheme={setTheme} />
  )
}

// Button.jsx
function Button({ theme, setTheme }) {
  return <button onClick={() => setTheme(...)}>...</button>
}
```

**問題点:**
- Navbar、Menuは`theme`を使わないのに、propsとして受け取る必要がある
- 中間のコンポーネントがすべて変更される
- 新しいpropsを追加すると、すべてのコンポーネントを修正する必要がある

#### Context APIの場合（良い例）

```jsx
// App.jsx
function App() {
  return (
    <ThemeProvider>
      <Navbar />
    </ThemeProvider>
  )
}

// Button.jsx（深い階層）
function Button() {
  const { theme, toggleTheme } = useTheme()
  return <button onClick={toggleTheme}>...</button>
}
```

**利点:**
- 中間のコンポーネント（Navbar、Menu）は何も知る必要がない
- Buttonで直接`useTheme()`を呼ぶだけ
- 新しいpropsを追加しても、使う場所だけ変更すればいい

## 理解を深めたポイント

### 1. Context APIの適切な使い所

**使うべき場合:**
- 3階層以上離れたコンポーネント間でデータを共有
- アプリ全体で使う設定やデータ（テーマ、言語、認証情報）
- 頻繁に更新されないグローバルな状態

**使うべきでない場合:**
- 隣接したコンポーネント間（propsで十分）
- 頻繁に更新される状態（パフォーマンス問題が起きる可能性）
- ローカルな状態（1つのコンポーネント内で完結する状態）

### 2. カスタムフックパターンの利点

```jsx
// 直接useContextを使う（良くない）
const theme = useContext(ThemeContext)

// カスタムフックを使う（良い）
const { theme, toggleTheme } = useTheme()
```

**利点:**
- エラーチェックが一箇所に集約
- 使い方がシンプル
- Contextの実装を隠蔽できる
- 将来的に実装を変更しても、使う側は影響を受けない

### 3. Providerパターンの設計

**良い設計:**
```jsx
const value = {
  theme,        // 状態
  isDark,       // 派生値
  toggleTheme,  // 関数
}
```

**ポイント:**
- 必要最小限のデータと関数のみ公開
- 派生値（`isDark`）も含めることで、使う側が楽になる
- 状態と操作関数をセットで提供

### 4. LocalStorageとの統合パターン

```jsx
// 読み込み
const [theme, setTheme] = useState(() => {
  const saved = localStorage.getItem('theme')
  return saved || 'light'
})

// 保存
useEffect(() => {
  localStorage.setItem('theme', theme)
}, [theme])
```

このパターンは他の設定にも応用できる:
- 言語設定
- フォントサイズ
- レイアウト設定

## 実務での応用例

### 1. 多言語対応（i18n）

```jsx
// LocaleContext.jsx
export function LocaleProvider({ children }) {
  const [locale, setLocale] = useState(() => {
    return localStorage.getItem('locale') || 'ja'
  })

  const t = (key) => {
    // 翻訳辞書から文字列を取得
    return translations[locale][key]
  }

  return (
    <LocaleContext.Provider value={{ locale, setLocale, t }}>
      {children}
    </LocaleContext.Provider>
  )
}

// 使用例
function Header() {
  const { t } = useLocale()
  return <h1>{t('welcome')}</h1>
}
```

### 3. ショッピングカート

```jsx
// CartContext.jsx
export function CartProvider({ children }) {
  const [items, setItems] = useState([])

  const addToCart = (product) => {
    setItems([...items, product])
  }

  const removeFromCart = (productId) => {
    setItems(items.filter(item => item.id !== productId))
  }

  const total = items.reduce((sum, item) => sum + item.price, 0)

  return (
    <CartContext.Provider value={{ items, addToCart, removeFromCart, total }}>
      {children}
    </CartContext.Provider>
  )
}
```

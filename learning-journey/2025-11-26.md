## 学習メモ

### React Routerの主要コンポーネント

#### BrowserRouter
アプリケーション全体をラップし、ルーティング機能を提供する最上位コンポーネント。

```jsx
import { BrowserRouter } from 'react-router-dom'

function App() {
  return (
    <BrowserRouter>
      {/* アプリのコンテンツ */}
    </BrowserRouter>
  )
}
```

#### Routes と Route
`Routes`は複数の`Route`をまとめる親コンポーネント。`Route`は`path`と`element`を指定してURLとコンポーネントを紐付ける。

```jsx
import { Routes, Route } from 'react-router-dom'

<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
  <Route path="/projects" element={<Projects />} />
  <Route path="*" element={<NotFound />} />
</Routes>
```

- `path="/"`: ホームページ（ルート）
- `path="/about"`: Aboutページ
- `path="*"`: どのパスにもマッチしなかった場合（404ページ用）

#### Link コンポーネント
`<a>`タグの代わりに使用。ページリロードなしで遷移できる。

```jsx
import { Link } from 'react-router-dom'

<Link to="/">Home</Link>
<Link to="/about">About</Link>
```

**従来の<a>タグとの違い:**
- `<a href="/about">`: ページ全体をリロード（遅い、チラつく）
- `<Link to="/about">`: JavaScriptでコンポーネントを切り替え（速い、滑らか）

### 動的ルートとuseParams

#### 動的パラメータの定義
`:id`のようにコロンを付けると、その部分が動的パラメータになる。

```jsx
<Route path="/projects/:id" element={<ProjectDetail />} />
```

この設定により、以下のようなURLがすべて同じコンポーネントにマッチする:
- `/projects/1` → `id = "1"`
- `/projects/2` → `id = "2"`
- `/projects/999` → `id = "999"`

#### useParamsフックの使い方
URLパラメータを取得するReact Routerのフック。

```jsx
import { useParams } from 'react-router-dom'

function ProjectDetail() {
  const { id } = useParams()  // URLから id を取得

  // id を使ってデータを取得
  const project = projects[id]

  return (
    <div>
      <h1>{project.name}</h1>
    </div>
  )
}
```

#### テンプレートリテラルで動的にリンクを生成

```jsx
{projects.map(project => (
  <Link to={`/projects/${project.id}`}>
    {project.name}
  </Link>
))}
```

- バッククォート（`` ` ``）を使用
- `${project.id}`で変数を埋め込む
- 各プロジェクトに応じたURLが生成される

### SPAの仕組み

React Routerを使ったSPA（Single Page Application）の動作フロー:

1. **初回ロード**: ブラウザが1つのHTMLファイルを取得
2. **Link クリック**: ユーザーがリンクをクリック
3. **URL 変更**: React RouterがブラウザのURL履歴APIを使ってURLを変更
4. **コンポーネント切り替え**: 新しいURLにマッチする`Route`を見つけ、対応するコンポーネントをレンダリング
5. **アニメーション**: CSSアニメーションでスムーズに表示

**メリット:**
- ページ全体のリロードが不要
- 高速なページ遷移
- スムーズなユーザー体験
- ネイティブアプリのような操作感

### ナビゲーションバーの実装

グラデーション背景とFlexboxレイアウトを使ったナビゲーションバー:

```css
.navbar {
  background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
}

.nav-container {
  display: flex;
  justify-content: space-between;
  align-items: center;
}

.nav-menu {
  display: flex;
  gap: 2rem;
}
```

**ポイント:**
- `linear-gradient`: 紫のグラデーション背景
- `justify-content: space-between`: ロゴとメニューを両端に配置
- `gap: 2rem`: メニュー項目間の間隔

### エラーハンドリング

存在しないプロジェクトIDへのアクセス時の処理:

```jsx
const project = projects[id]

if (!project) {
  return (
    <div className="page">
      <h1>プロジェクトが見つかりません</h1>
      <Link to="/projects">← プロジェクト一覧に戻る</Link>
    </div>
  )
}
```

ユーザーが間違ったURLを入力しても、適切なメッセージとナビゲーションを提供。

## 理解を深めたポイント

### 1. React Routerの必要性
複数ページを持つWebアプリケーションでは、ページ間の遷移が必要。React Routerを使うことで:
- URLに応じて異なるコンポーネントを表示
- ブラウザの戻る/進むボタンが正しく動作
- URLを共有できる（特定のページに直接アクセス可能）

### 2. コンポーネントベースのルーティング
各ページを独立したコンポーネントとして作成し、React Routerで管理することで:
- コードの見通しが良くなる
- 再利用しやすい
- メンテナンスが簡単

### 3. 動的ルートの実用性
1つのコンポーネントで複数の似た構造のページを管理できる:
- ブログ記事一覧 → 記事詳細
- 商品一覧 → 商品詳細
- ユーザー一覧 → ユーザープロフィール

実際のアプリケーションでは、APIからデータを取得してIDに応じた内容を表示することが多い。

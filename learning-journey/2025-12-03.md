## 学習メモ

### シフトレフトアプローチとは

**従来の開発フロー（ウォーターフォール型）**:
```
要件定義 → 設計 → 実装 → テスト → リリース
                            ↑
                         ここでバグ発見
```

**シフトレフトアプローチ**:
```
要件定義 → [テスト観点レビュー] → 設計 → [テスト観点レビュー] → ...
   ↑                              ↑
早期にテスト観点を導入してバグを防ぐ
```

**メリット**:
- 要件の曖昧さを早期発見
- 手戻りコストの削減
- テスタビリティの高い設計

---

### INVEST原則（良いユーザーストーリーの条件）

| 項目 | 説明 | 例 |
|------|------|-----|
| **I**ndependent | 他のストーリーに依存しない | 「ログイン機能」と「記事投稿」は独立 |
| **N**egotiable | 詳細は交渉可能 | 「記事投稿」の細かいUIは後で決定OK |
| **V**aluable | ユーザーに価値を提供 | 「記事を投稿できる」→ブログの本質的価値 |
| **E**stimable | 実装規模が見積もれる | 「記事投稿フォーム」は1-2日で完了 |
| **S**mall | 小さく分割されている | 「SNS機能全部」ではなく「コメント機能」 |
| **T**estable | テスト可能 | 「記事が保存される」を確認できる |

### Next.js 14 App Routerの重要概念

#### 1. Server Components vs Client Components

**Server Components（デフォルト）**:
```typescript
// app/page.tsx
async function HomePage() {
  const posts = await prisma.post.findMany() // サーバー側で実行
  return <PostList posts={posts} />
}
```
- サーバー側でレンダリング
- データフェッチがサーバーで完結
- SEO対応、初回ロード高速

**Client Components**:
```typescript
'use client' // この宣言が必要

export function PostEditor() {
  const [title, setTitle] = useState('')
  // インタラクティブな処理
}
```
- ブラウザで実行
- useState, useEffectなどのフックが使える
- ユーザーインタラクションが必要な場合

#### 2. Route Groups

ディレクトリ名を`()`で囲むとURLに含まれない:

```
app/
├── (auth)/          # URL: /login, /register
│   ├── login/
│   ├── register/
│   └── layout.tsx   # 認証ページ専用レイアウト
├── (main)/          # URL: /, /posts/123
│   ├── page.tsx
│   └── layout.tsx   # メインページ用レイアウト
```

### Prismaのリレーション定義

#### 1対多（1:N）
```prisma
model User {
  id    String @id
  posts Post[]  // 1ユーザーは複数の記事を持つ
}

model Post {
  id       String @id
  authorId String
  author   User   @relation(fields: [authorId], references: [id])
}
```

#### 多対多（M:N）
```prisma
model Post {
  id   String    @id
  tags PostTag[]  // 中間テーブル経由
}

model Tag {
  id    String    @id
  posts PostTag[]
}

model PostTag {
  postId String
  tagId  String
  post   Post @relation(fields: [postId], references: [id])
  tag    Tag  @relation(fields: [tagId], references: [id])

  @@id([postId, tagId])  // 複合主キー
}
```

### N+1問題とその解決

**悪い例（N+1問題）**:
```typescript
// 1回のクエリで記事を取得
const posts = await prisma.post.findMany() // 1回

// N回のクエリで著者を取得（記事の数だけループ）
for (const post of posts) {
  const author = await prisma.user.findUnique({
    where: { id: post.authorId }
  }) // N回
}
// 合計: 1 + N 回のクエリ
```

**良い例（Eager Loading）**:
```typescript
// 1回のクエリで記事と著者を同時取得
const posts = await prisma.post.findMany({
  include: {
    author: true  // JOINで一度に取得
  }
}) // 1回のクエリ
```

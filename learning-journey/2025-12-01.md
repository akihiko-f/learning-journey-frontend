### パフォーマンス最適化の3つの柱

#### 1. useMemo - 計算結果のメモ化

**使う場面：**
- 重い計算処理がある場合
- 配列やオブジェクトの生成コストが高い場合
- レンダリングごとに同じ計算を繰り返している場合

**基本構文：**
```jsx
const calculation = useMemo(() => {
  return expensiveCalculation(input)
}, [input])
```

**ポイント：**
- 第1引数：計算を行う関数
- 第2引数：依存配列（これが変わったときだけ再計算）
- 依存配列が空`[]`の場合、初回のみ計算

**実装例：**
```jsx
function PerformanceDemo() {
  const [count, setCount] = useState(0)
  const [input, setInput] = useState(5)

  // useMemoなし: countが変わるたびに重い計算が実行される
  // const calculation = expensiveCalculation(input)

  // useMemoあり: inputが変わったときだけ計算される
  const calculation = useMemo(() => {
    return expensiveCalculation(input)
  }, [input])

  return (
    <div>
      {/* カウントボタンを押しても、calculationは再計算されない */}
      <button onClick={() => setCount(count + 1)}>Count: {count}</button>
      <p>計算結果: {calculation}</p>
    </div>
  )
}
```

**効果：**
- `count`が変わっても`expensiveCalculation()`は実行されない
- `input`が変わったときだけ再計算される
- パフォーマンスが向上

#### 2. useCallback - 関数のメモ化

**使う場面：**
- 子コンポーネントにpropsとして関数を渡す場合
- React.memoと組み合わせる場合
- useEffectやuseMemoの依存配列に関数を含める場合

**基本構文：**
```jsx
const handleClick = useCallback(() => {
  doSomething()
}, [])
```

**なぜ必要？**

JavaScriptでは、**関数は毎回新しい参照として作られる**：

```jsx
function Parent() {
  const [count, setCount] = useState(0)

  // このhandleClickは、レンダリングごとに新しい関数として作られる
  const handleClick = () => {
    console.log('clicked')
  }

  // 子コンポーネントにとって、handleClickは毎回「新しいprops」
  return <Child onClick={handleClick} />
}
```

**useCallbackで解決：**

```jsx
function Parent() {
  const [count, setCount] = useState(0)

  // useCallbackで関数をメモ化 → 同じ参照を保持
  const handleClick = useCallback(() => {
    console.log('clicked')
  }, [])

  // 子コンポーネントにとって、handleClickは常に「同じprops」
  return <Child onClick={handleClick} />
}
```

**実装例：**
```jsx
function PerformanceDemo() {
  const [count, setCount] = useState(0)

  // useCallbackなし: countが変わるたびに新しい関数が作られる
  // const handleIncrement = () => setCount(prev => prev + 1)

  // useCallbackあり: 関数の参照が保持される
  const handleIncrement = useCallback(() => {
    setCount(prev => prev + 1)
  }, [])

  return <MemoizedButton onClick={handleIncrement}>+1</MemoizedButton>
}
```

**重要な注意点：**

依存配列に含める値：
```jsx
// ❌ 間違い: countに依存しているのに依存配列に含めていない
const handleClick = useCallback(() => {
  console.log(count)
}, [])

// ✅ 正しい: countに依存している場合は依存配列に含める
const handleClick = useCallback(() => {
  console.log(count)
}, [count])

// ✅ ベスト: prev関数を使えば依存配列が不要
const handleIncrement = useCallback(() => {
  setCount(prev => prev + 1)
}, [])
```

#### 3. React.memo - コンポーネントのメモ化

**使う場面：**
- 同じpropsで頻繁に再レンダリングされるコンポーネント
- リストアイテムなど、多数のコンポーネントをレンダリングする場合
- 重い処理を含むコンポーネント

**基本構文：**
```jsx
const MemoizedComponent = memo(function Component({ prop1, prop2 }) {
  return <div>{prop1} {prop2}</div>
})
```

**動作原理：**

React.memoは**propsの浅い比較**を行う：
```jsx
// 前回のprops
{ name: "Alice", age: 30 }

// 今回のprops
{ name: "Alice", age: 30 }

// 浅い比較: name === name && age === age
// → trueなので再レンダリングしない
```

**問題：オブジェクトや関数は参照が変わる**

```jsx
function Parent() {
  const [count, setCount] = useState(0)

  // 毎回新しいオブジェクトが作られる
  const config = { theme: 'dark' }

  // 毎回新しい関数が作られる
  const handleClick = () => console.log('clicked')

  // React.memoを使っていても、propsが毎回「違う」と判断される
  return <MemoizedChild config={config} onClick={handleClick} />
}
```

**解決策：useMemoとuseCallbackを組み合わせる**

```jsx
function Parent() {
  const [count, setCount] = useState(0)

  // useMemoでオブジェクトの参照を保持
  const config = useMemo(() => ({ theme: 'dark' }), [])

  // useCallbackで関数の参照を保持
  const handleClick = useCallback(() => {
    console.log('clicked')
  }, [])

  // これでReact.memoが正しく機能する
  return <MemoizedChild config={config} onClick={handleClick} />
}
```

**実装例（今回のデモ）：**

```jsx
// メモ化されていないボタン
function RegularButton({ onClick, children }) {
  console.log(`RegularButton "${children}" rendered`)
  return <button onClick={onClick}>{children}</button>
}

// React.memoでメモ化されたボタン
const MemoizedButton = memo(function Button({ onClick, children }) {
  console.log(`MemoizedButton "${children}" rendered`)
  return <button onClick={onClick}>{children}</button>
})

function PerformanceDemo() {
  const [count, setCount] = useState(0)

  // useCallbackで関数をメモ化
  const handleIncrement = useCallback(() => {
    setCount(prev => prev + 1)
  }, [])

  return (
    <div>
      <p>Count: {count}</p>

      {/* RegularButton: countが変わるたびに再レンダリング */}
      <RegularButton onClick={handleIncrement}>+1</RegularButton>

      {/* MemoizedButton: propsが変わらないので再レンダリングされない */}
      <MemoizedButton onClick={handleIncrement}>+1</MemoizedButton>
    </div>
  )
}
```

**結果：**
- インクリメントボタンを押すと、`count`が変わる
- 親コンポーネント（PerformanceDemo）は再レンダリングされる
- RegularButtonも再レンダリングされる（コンソールにログが出る）
- MemoizedButtonは再レンダリングされない（コンソールにログが出ない）
  - なぜなら、`onClick`（useCallbackでメモ化）と`children`（文字列）が変わっていないから

### パフォーマンス最適化の組み合わせパターン

#### パターン1: useMemo + useCallback + React.memo

**最強の組み合わせ：**
```jsx
function Parent() {
  const [items, setItems] = useState([...])

  // 1. useMemoで重い計算をメモ化
  const sortedItems = useMemo(() => {
    console.log('ソート実行中...')
    return items.sort((a, b) => a.price - b.price)
  }, [items])

  // 2. useCallbackで関数をメモ化
  const handleDelete = useCallback((id) => {
    setItems(prev => prev.filter(item => item.id !== id))
  }, [])

  return (
    <div>
      {sortedItems.map(item => (
        // 3. React.memoで子コンポーネントをメモ化
        <MemoizedItemCard
          key={item.id}
          item={item}
          onDelete={handleDelete}
        />
      ))}
    </div>
  )
}

// React.memoで子コンポーネントをメモ化
const MemoizedItemCard = memo(function ItemCard({ item, onDelete }) {
  console.log(`ItemCard ${item.id} rendered`)

  return (
    <div>
      <h3>{item.name}</h3>
      <button onClick={() => onDelete(item.id)}>削除</button>
    </div>
  )
})
```

**効果：**
- `items`が変わったときだけソートが実行される
- `handleDelete`の参照が保持される
- 各ItemCardは、自分の`item`が変わったときだけ再レンダリング
- 他のアイテムが変わっても、無関係なItemCardは再レンダリングされない

### Strict Modeとは

**Strict Modeの役割：**

React 18のStrict Modeは、開発時に**コンポーネントを2回レンダリング**することで、副作用のバグを早期発見します。

**なぜ2回レンダリング？**

```jsx
function Component() {
  useEffect(() => {
    // 副作用（例: イベントリスナー登録）
    window.addEventListener('resize', handleResize)

    // ❌ クリーンアップを忘れた！
    // return () => window.removeEventListener('resize', handleResize)
  }, [])

  return <div>...</div>
}
```

**Strict Modeなし：**
- コンポーネントが1回マウント → イベントリスナー1個
- バグに気づかない

**Strict Modeあり：**
- コンポーネントが2回マウント → イベントリスナー2個
- バグが顕在化 → 開発者が気づく

**Strict Modeの動作：**

```jsx
// main.jsxまたはApp.jsx
import { StrictMode } from 'react'

<StrictMode>
  <App />
</StrictMode>
```

**開発モード：**
1. マウント
2. アンマウント
3. 再マウント

**本番モード：**
- 通常通り1回だけマウント

**今回のデモでの影響：**

```jsx
const MemoizedButton = memo(function Button({ onClick, children }) {
  console.log(`MemoizedButton "${children}" rendered`)
  return <button onClick={onClick}>{children}</button>
})
```

**初回レンダリング時：**
- Strict Modeにより2回レンダリング
- コンソールに2回ログが表示される

**インクリメントボタンを押した後：**
- RegularButtonは再レンダリング → ログが2回出る（Strict Mode）
- MemoizedButtonは再レンダリングされない → ログが出ない

これが**React.memoが正しく動作している証拠**。

### 最適化のベストプラクティス

#### 1. 早すぎる最適化は悪

```jsx
// ❌ 悪い例: すべてをメモ化
function SimpleCounter() {
  const [count, setCount] = useState(0)

  // 不要なuseMemo（単純な計算）
  const doubled = useMemo(() => count * 2, [count])

  // 不要なuseCallback（子コンポーネントがない）
  const increment = useCallback(() => setCount(prev => prev + 1), [])

  return (
    <div>
      <p>{count}</p>
      <p>{doubled}</p>
      <button onClick={increment}>+1</button>
    </div>
  )
}

// ✅ 良い例: シンプルに書く
function SimpleCounter() {
  const [count, setCount] = useState(0)

  const doubled = count * 2

  return (
    <div>
      <p>{count}</p>
      <p>{doubled}</p>
      <button onClick={() => setCount(prev => prev + 1)}>+1</button>
    </div>
  )
}
```

**理由：**
- useMemoやuseCallbackにもコストがある（メモリとCPU）
- 単純な処理なら、メモ化しない方が速い
- コードが複雑になり、読みづらくなる

#### 2. 最適化が必要な場面

**useMemoを使うべき：**
- ループや複雑な計算がある
- 配列やオブジェクトの生成コストが高い
- レンダリングが遅いと感じる

**useCallbackを使うべき：**
- React.memoと組み合わせる
- useEffectやuseMemoの依存配列に関数を含める
- 子コンポーネントに関数を渡す

**React.memoを使うべき：**
- リストアイテムなど、大量にレンダリングされる
- 同じpropsで頻繁に再レンダリングされる
- 重い処理を含むコンポーネント

#### 3. パフォーマンス測定

最適化の前後で必ず測定：
```jsx
// React Developer Toolsの「Profiler」を使う
// または、console.timeを使う
console.time('レンダリング')
// レンダリング処理
console.timeEnd('レンダリング')
```

#### 4. 依存配列のルール

**必ず含める：**
- 関数内で使用する全てのprops、state、変数

**含めなくていい：**
- setState関数（`setCount`など）
- useRefで作った参照
- 定数

```jsx
// ✅ 正しい
const handleClick = useCallback(() => {
  console.log(count) // countを使っている
}, [count]) // countを依存配列に含める

// ❌ 間違い
const handleClick = useCallback(() => {
  console.log(count) // countを使っている
}, []) // 依存配列に含めていない → 古いcountを参照し続ける
```

## 理解を深めたポイント

### 1. React.memoとuseCallbackは対

React.memoだけでは効果がない場合がある：

```jsx
// React.memoだけでは不十分
const MemoizedButton = memo(function Button({ onClick }) {
  return <button onClick={onClick}>Click</button>
})

function Parent() {
  const [count, setCount] = useState(0)

  // 毎回新しい関数が作られる → propsが変わる → React.memoが効かない
  const handleClick = () => console.log('clicked')

  return <MemoizedButton onClick={handleClick} />
}

// useCallbackと組み合わせて初めて効果を発揮
function Parent() {
  const [count, setCount] = useState(0)

  // 同じ関数参照を保持 → propsが変わらない → React.memoが効く
  const handleClick = useCallback(() => {
    console.log('clicked')
  }, [])

  return <MemoizedButton onClick={handleClick} />
}
```

### 2. 浅い比較の重要性

React.memoは**浅い比較**しか行わない：

```jsx
// ❌ 毎回再レンダリングされる
function Parent() {
  const [count, setCount] = useState(0)

  // 毎回新しい配列が作られる
  const items = [1, 2, 3]

  return <MemoizedList items={items} />
}

// ✅ メモ化により再レンダリングされない
function Parent() {
  const [count, setCount] = useState(0)

  // useMemoで配列の参照を保持
  const items = useMemo(() => [1, 2, 3], [])

  return <MemoizedList items={items} />
}
```

### 3. prev関数パターン

依存配列を減らすテクニック：

```jsx
// ❌ 依存配列にcountを含める必要がある
const handleIncrement = useCallback(() => {
  setCount(count + 1)
}, [count])

// ✅ prev関数を使えば依存配列が不要
const handleIncrement = useCallback(() => {
  setCount(prev => prev + 1)
}, [])
```

### 4. 最適化の優先順位

1. **まず動くコードを書く**
2. **遅いと感じたら測定する**
3. **ボトルネックを特定する**
4. **必要な箇所だけ最適化する**

## まとめ

### パフォーマンス最適化の3つの柱

| 最適化手法 | 用途 | 使う場面 |
|-----------|------|---------|
| useMemo | 値のメモ化 | 重い計算、配列/オブジェクト生成 |
| useCallback | 関数のメモ化 | 子コンポーネントへの関数渡し |
| React.memo | コンポーネントのメモ化 | propsが変わらない子コンポーネント |

### 最も重要な原則

**「早すぎる最適化は悪」**

- 最初からすべてをメモ化しない
- 遅いと感じてから最適化する
- パフォーマンス測定を忘れずに
- 必要な箇所だけ最適化する

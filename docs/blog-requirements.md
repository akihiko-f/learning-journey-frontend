# 要件定義書 - シンプルブログアプリ

## プロジェクト概要

### プロジェクト名
**SimpleBlog** - 学習用ブログプラットフォーム

### 目的
Phase 5（実践的な開発プロセス）の学習教材として、要件定義から実装・テストまでの全工程を体験するためのブログアプリケーションを開発する。

**学習目標:**
- ドキュメント駆動開発の実践
- TDD/ATDDによる品質保証
- Next.js（App Router）を使ったフルスタック開発
- 認証・認可の実装
- ファイルアップロード機能の実装
- リアルタイム機能の実装

### ターゲットユーザー
- **ブログ投稿者**: 技術記事や学習記録を公開したい個人ユーザー
- **ブログ読者**: 記事を読み、コメントやリアクションをしたいユーザー
- **管理者**: コンテンツを管理し、不適切な投稿を削除できるユーザー

---

## ユーザーストーリー

### ストーリー1: ユーザー登録とログイン
**As a** 新規ユーザー
**I want** メールアドレスとパスワードでアカウントを作成したい
**So that** ブログ記事を投稿したり、コメントを残せるようになる

**受け入れ基準**:
- [ ] メールアドレス、ユーザー名、パスワードで新規登録できる
- [ ] 登録済みユーザーはメールアドレスとパスワードでログインできる
- [ ] ログイン状態がセッションで保持される
- [ ] ログアウト機能が動作する

---

### ストーリー2: ブログ記事の投稿
**As a** ログイン済みユーザー
**I want** タイトル、本文、アイキャッチ画像を含む記事を投稿したい
**So that** 自分の知識や経験を他のユーザーと共有できる

**受け入れ基準**:
- [ ] タイトルと本文を入力して記事を作成できる
- [ ] アイキャッチ画像をアップロードできる
- [ ] マークダウン形式で本文を記述できる
- [ ] 記事にタグを付与できる
- [ ] 下書き保存と公開の切り替えができる

---

### ストーリー3: 記事の閲覧とコメント
**As a** ブログ読者
**I want** 公開されている記事を閲覧し、コメントを残したい
**So that** 著者や他の読者と意見交換ができる

**受け入れ基準**:
- [ ] 記事一覧ページで全ての公開記事が表示される
- [ ] 記事詳細ページで本文とコメントが表示される
- [ ] ログイン済みユーザーはコメントを投稿できる
- [ ] コメントは投稿順に表示される

---

### ストーリー4: リアルタイム通知
**As a** 記事投稿者
**I want** 自分の記事に新しいコメントが付いたときにリアルタイムで通知を受け取りたい
**So that** すぐに反応して対話できる

**受け入れ基準**:
- [ ] 新しいコメントが投稿されたときに通知が表示される
- [ ] 通知一覧ページで過去の通知を確認できる
- [ ] 未読/既読の状態管理ができる

---

### ストーリー5: ユーザープロフィール
**As a** ログイン済みユーザー
**I want** 自分のプロフィール情報を編集したい
**So that** 他のユーザーに自己紹介できる

**受け入れ基準**:
- [ ] プロフィール画像をアップロードできる
- [ ] ユーザー名、自己紹介文を編集できる
- [ ] 自分の投稿記事一覧を表示できる

---

### ストーリー6: 記事の検索
**As a** ブログ読者
**I want** キーワードやタグで記事を検索したい
**So that** 興味のある記事を素早く見つけられる

**受け入れ基準**:
- [ ] タイトルと本文からキーワード検索ができる
- [ ] タグで記事をフィルタリングできる
- [ ] 検索結果が関連度順に表示される

## 機能要件

### 必須機能（MVP: Minimum Viable Product）

#### 機能1: ユーザー認証
- **説明**: ユーザー登録、ログイン、ログアウト機能
- **受け入れ基準**:
  - [ ] メールアドレス、ユーザー名、パスワードで新規登録できる
  - [ ] パスワードは暗号化して保存される（bcrypt）
  - [ ] ログイン済みユーザーのみ記事投稿・コメント可能
  - [ ] セッションは7日間有効
  - [ ] ログアウト機能が動作する

#### 機能2: 記事管理（CRUD）
- **説明**: 記事の作成、表示、編集、削除機能
- **受け入れ基準**:
  - [ ] ログイン済みユーザーは記事を作成できる
  - [ ] 記事の所有者のみ編集・削除できる
  - [ ] 下書き/公開の状態管理ができる
  - [ ] マークダウンエディタで本文を記述できる
  - [ ] アイキャッチ画像をアップロードできる（画像はCloudinaryまたはローカル保存）
  - [ ] タグを最大5個まで設定できる

#### 機能3: 記事一覧・詳細表示
- **説明**: 公開記事の一覧表示と詳細ページ
- **受け入れ基準**:
  - [ ] 公開されている記事のみ一覧に表示される
  - [ ] ページネーション（10件/ページ）
  - [ ] 記事詳細ページでマークダウンがHTMLに変換される
  - [ ] 投稿者名、投稿日時、タグが表示される

#### 機能4: コメント機能
- **説明**: 記事へのコメント投稿と表示
- **受け入れ基準**:
  - [ ] ログイン済みユーザーのみコメント投稿可能
  - [ ] コメントは投稿順に表示される
  - [ ] コメント投稿者のみ削除可能

### 推奨機能（Nice to Have）

#### 機能A: リアルタイム通知
- **説明**: WebSocketまたはServer-Sent Eventsを使った新着通知
- **優先度**: 高
- **受け入れ基準**:
  - [ ] 新しいコメントが投稿されたときに記事投稿者に通知
  - [ ] 通知一覧ページで過去の通知を確認可能
  - [ ] 未読/既読の状態管理

#### 機能B: 記事検索
- **説明**: キーワードとタグによる記事検索
- **優先度**: 中
- **受け入れ基準**:
  - [ ] タイトル・本文からキーワード検索（部分一致）
  - [ ] タグでフィルタリング
  - [ ] 検索結果のページネーション

#### 機能C: ユーザープロフィール
- **説明**: ユーザー情報の表示と編集
- **優先度**: 中
- **受け入れ基準**:
  - [ ] プロフィール画像のアップロード
  - [ ] 自己紹介文の編集
  - [ ] ユーザーの投稿記事一覧表示

#### 機能D: いいね機能
- **説明**: 記事やコメントにリアクションを付与
- **優先度**: 低
- **受け入れ基準**:
  - [ ] ログイン済みユーザーは記事にいいねできる
  - [ ] いいねは1ユーザー1回まで
  - [ ] いいね数が表示される

#### 機能E: 記事の公開/非公開管理
- **説明**: 管理者が不適切な記事を非公開にできる
- **優先度**: 中
- **受け入れ基準**:
  - [ ] 管理者ロールを持つユーザーが存在する
  - [ ] 管理者は全ての記事を非公開にできる
  - [ ] 非公開にされた記事は一覧・詳細ページで表示されない

## バリデーションルール

入力値の制約とエラーハンドリングを明確に定義します。

### ユーザー登録・ログイン

#### メールアドレス
- **形式**: RFC 5322準拠のメールアドレス形式
- **最大文字数**: 254文字
- **重複チェック**: 既に登録済みのメールアドレスは使用不可
- **エラーメッセージ**:
  - 形式エラー: "有効なメールアドレスを入力してください"
  - 重複エラー: "このメールアドレスは既に登録されています"

#### パスワード
- **最小文字数**: 8文字
- **最大文字数**: 128文字
- **必須要素**: 英数字を含む（記号は任意）
- **エラーメッセージ**:
  - 短すぎる: "パスワードは8文字以上で入力してください"
  - 弱い: "パスワードには英字と数字を含めてください"

#### ユーザー名
- **最小文字数**: 2文字
- **最大文字数**: 30文字
- **使用可能文字**: 半角英数字、アンダースコア、ハイフン
- **重複チェック**: 既に使用されているユーザー名は使用不可
- **エラーメッセージ**:
  - 形式エラー: "ユーザー名は半角英数字、アンダースコア、ハイフンのみ使用できます"
  - 重複エラー: "このユーザー名は既に使用されています"

### 記事投稿

#### タイトル
- **最小文字数**: 1文字
- **最大文字数**: 100文字
- **必須**: Yes
- **エラーメッセージ**:
  - 未入力: "タイトルを入力してください"
  - 長すぎる: "タイトルは100文字以内で入力してください"

#### 本文
- **最小文字数**: 1文字
- **最大文字数**: 50,000文字
- **必須**: Yes
- **形式**: Markdown
- **エラーメッセージ**:
  - 未入力: "本文を入力してください"
  - 長すぎる: "本文は50,000文字以内で入力してください"

#### タグ
- **最小個数**: 0個
- **最大個数**: 5個
- **タグ名の最大文字数**: 20文字
- **使用可能文字**: 日本語、英数字、アンダースコア、ハイフン
- **エラーメッセージ**:
  - 個数超過: "タグは最大5個まで設定できます"
  - 文字数超過: "タグは20文字以内で入力してください"

#### アイキャッチ画像
- **ファイル形式**: JPEG, PNG, WebP, GIF
- **最大ファイルサイズ**: 5MB
- **推奨サイズ**: 1200x630px（OGP推奨サイズ）
- **エラーメッセージ**:
  - 形式エラー: "JPEG、PNG、WebP、GIF形式の画像をアップロードしてください"
  - サイズ超過: "画像サイズは5MB以下にしてください"

### コメント

#### コメント本文
- **最小文字数**: 1文字
- **最大文字数**: 1,000文字
- **必須**: Yes
- **エラーメッセージ**:
  - 未入力: "コメントを入力してください"
  - 長すぎる: "コメントは1,000文字以内で入力してください"

### プロフィール

#### 自己紹介文
- **最小文字数**: 0文字（任意）
- **最大文字数**: 500文字
- **エラーメッセージ**:
  - 長すぎる: "自己紹介は500文字以内で入力してください"

#### プロフィール画像
- **ファイル形式**: JPEG, PNG, WebP, GIF
- **最大ファイルサイズ**: 2MB
- **推奨サイズ**: 400x400px（正方形）
- **エラーメッセージ**:
  - 形式エラー: "JPEG、PNG、WebP、GIF形式の画像をアップロードしてください"
  - サイズ超過: "画像サイズは2MB以下にしてください"

### エラーハンドリング

#### ネットワークエラー
- **タイムアウト**: APIリクエストは30秒でタイムアウト
- **リトライ**: 失敗時は最大3回まで自動リトライ（指数バックオフ）
- **エラーメッセージ**: "ネットワークエラーが発生しました。しばらくしてからもう一度お試しください"

#### サーバーエラー
- **5xx エラー**: "サーバーエラーが発生しました。しばらくしてからもう一度お試しください"
- **4xx エラー**: 各エラーコードに応じた具体的なメッセージ

#### 並行処理
- **二重送信防止**: 送信ボタンを押した後、処理完了までボタンを無効化
- **同時編集**: 最後に保存した内容が優先される（楽観的ロック）
- **エラーメッセージ**: "この記事は他のユーザーによって更新されています。ページを再読み込みしてください"

### 境界値テスト

以下の境界値で動作を確認：
- 文字数: 0文字、1文字、上限-1文字、上限文字、上限+1文字
- ファイルサイズ: 0バイト、1バイト、上限-1バイト、上限バイト、上限+1バイト
- タグ数: 0個、1個、5個、6個
- ページネーション: 1ページ目、最終ページ、最終ページ+1

## 非機能要件

### パフォーマンス
- [ ] ページ読み込み時間: 初回3秒以内、2回目以降1秒以内（Next.jsのキャッシュ活用）
- [ ] API レスポンス時間: 500ms以内（単純なクエリ）、1秒以内（複雑なクエリ）
- [ ] 画像の最適化: Next.js Image コンポーネントで自動最適化

### セキュリティ
- [ ] ユーザー認証: NextAuth.js（Credentials Provider）
- [ ] パスワード暗号化: bcrypt（saltRounds: 10）
- [ ] HTTPS通信: 本番環境で必須（Vercelデフォルト）
- [ ] CSRF対策: NextAuth.jsの組み込み機能
- [ ] XSS対策: React自動エスケープ + DOMPurifyでマークダウンサニタイズ
- [ ] SQL Injection対策: Prismaのパラメータ化クエリ
- [ ] 環境変数の保護: `.env.local`をgitignore

### 可用性
- [ ] 稼働率: 99%以上（Vercelの標準SLA）
- [ ] ダウンタイム: 計画メンテナンス時を除き最小化
- [ ] エラーハンドリング: 全APIルートでtry-catch実装

### ユーザビリティ
- [ ] レスポンシブデザイン（モバイル、タブレット、デスクトップ対応）
- [ ] アクセシビリティ対応（WCAG 2.1 AA準拠）
  - キーボードナビゲーション
  - スクリーンリーダー対応（ARIA属性）
  - 十分なコントラスト比
- [ ] 多言語対応: 不要（日本語のみ）
- [ ] ローディング状態の表示

### 保守性
- [ ] コードカバレッジ: 80%以上
  - 単体テスト: 80%以上
  - E2Eテスト: 主要フロー100%
- [ ] ドキュメント整備: 全ドキュメントテンプレート完備
- [ ] エラーログ記録: console.errorとファイルログ
- [ ] TypeScript: 厳格な型チェック（strict mode）

- **開発環境**: macOS（M1以降推奨）、Node.js 18以上
- **ブラウザサポート**: 最新のChrome、Firefox、Safari、Edge
- **データ量制限**: 初期は100記事、1000ユーザー程度を想定

---

## リスク

### リスク1: リアルタイム通知の実装難易度
- **発生確率**: 中
- **影響度**: 中
- **対策**:
  - 優先度を「推奨機能」に設定し、時間不足の場合はスキップ可能に
  - Server-Sent Events（SSE）で簡易実装を試みる
  - 最悪の場合、ポーリングで代替

### リスク2: 画像アップロード機能の複雑さ
- **発生確率**: 低
- **影響度**: 中
- **対策**:
  - Cloudinaryを使用して実装を簡略化
  - UploadThingなどの既存サービスを活用
  - ファイルサイズ・形式の制限を明確に

### リスク3: テストカバレッジ80%の達成
- **発生確率**: 中
- **影響度**: 低
- **対策**:
  - TDD/ATDDを徹底してテストを先に書く
  - 重要な機能から優先的にテストを作成
  - カバレッジレポートを定期的に確認

### リスク4: Next.js App Routerの学習コスト
- **発生確率**: 中
- **影響度**: 中
- **対策**:
  - 公式ドキュメントを参照しながら進める
  - 段階的に機能を実装し、焦らない
  - 分からないことはその都度質問・検索
